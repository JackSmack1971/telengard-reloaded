## Status

Blocked behind TEL-129 acceptance. Second implementation slice for the
Five-Floor MVP Demo.

## Design intent

Connect the already-authored production first-slice content to normal hosted
Godot play so exploration can naturally produce monsters, feature interactions,
and unsecured treasure without test fixtures or debug commands.

## Current gap

The production content pack contains floors 1–5 encounter, feature, and loot
data, while Core contains the corresponding resolvers. The hosted Godot session
does not yet compose those data/resolver paths into ordinary movement and
interaction.

## Requirements

- Resolve the current floor's encounter table through `ContentPack` and supply
  its deterministic trigger configuration to normal movement.
- Use explicit configurable encounter trigger tuning; do not invent a hidden
  permanent probability.
- Instantiate first-slice feature runtime state deterministically for the hosted
  floors using authored feature definitions and existing Core feature contracts.
- Route feature interaction through the appropriate existing fountain, altar,
  pit, or teleporter outcome path rather than generic renderer-owned effects.
- Ensure feature discovery/observation remains consistent with hidden-information
  rules.
- Resolve first-slice loot through the production loot tables and existing
  treasure acquisition boundary.
- Put acquired gold/items into unsecured expedition state using existing Core
  rules.
- Surface enough renderer-safe feedback for the player to recognize encounter,
  feature, and treasure events.

## Non-goals

- No new monster/item/feature/loot content.
- No permanent encounter/drop-rate balancing decision.
- No new feature mechanics where the source specification leaves semantics
  unresolved.
- No inventory-management redesign.
- No save/resume client integration.
- No production art.

## Invariants

Content data remains separate from runtime state. Deterministic RNG remains
scoped. Godot does not choose authoritative encounter outcomes, feature effects,
or loot results. Hidden feature/monster facts remain redacted until observed.
Carried/unsecured and secured progress remain distinct.

## Save/version impact

Expected none if the existing runtime/save contracts are sufficient. Any missing
persisted state discovered by the integration must be assigned explicitly
rather than hidden in host or presentation state.

## Tests / observation

- Focused host/integration tests proving normal movement can trigger an authored
  first-slice encounter.
- Deterministic feature-instance/outcome checks for a fixed seed.
- Treasure acquisition checks proving production loot reaches unsecured
  expedition state.
- Hidden-information checks for unobserved features/monsters.
- Godot observation of at least one encounter, one feature interaction, and one
  treasure acquisition through normal input.
- Canonical full repository verification.

## Acceptance criteria

With TEL-129's floor-aware session in place, normal Godot exploration using the
production first-slice content can produce an authored encounter, an authored
feature interaction, and unsecured treasure through existing authoritative Core
boundaries without debug commands or renderer-owned gameplay rules.
