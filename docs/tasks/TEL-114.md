# TEL-114 — Author first-slice loot tables

## Status

Not started.

## Design Intent

Author first-slice loot tables that resolve to TEL-113 item IDs and feed the
existing deterministic loot selection and carried-wealth boundary.

## Specification References

§9.5; §17; §29; §34; §36; §42; §48; §51.

## Dependencies

- TEL-109 — catalog, table schema, validation, and `content_version`.
- TEL-113 — item IDs referenced by the tables.
- TEL-105 — existing treasure acquisition and unsecured expedition-state
  boundary.

## Requirements

- Provide the loot tables referenced by the first-slice band/monster content.
- Reference only valid TEL-113 item IDs and use explicit positive weights with
  stable ordering.
- Make tables consumable by the existing `LootTableEngine` and treasure
  acquisition path without adding a second loot resolver.
- Keep table identity, selection inputs, and `content_version` stable for
  deterministic replay.
- Keep item value, gold outcomes, artifact chance, affixes, curses, and depth
  policy in existing/configurable contracts rather than smuggling formulas
  into table files.

## Non-Goals

- No new loot algorithm, item-instance ownership model, treasure command,
  wealth conversion, death-loss rule, or renderer behavior.
- No permanent drop-rate, value, artifact, curse, affix, or loss formula where
  the specification is silent. Mark it
  `CONFIGURATION/TUNING DECISION REQUIRED`.
- No tables for floors or content outside the first slice.

## Invariants

- Loot remains unsecured while underground and is secured only by the
  existing safety-boundary transition.
- Equal seed, content version, table, position, expedition, and acquisition
  count produce equal selection.
- Table definitions do not reveal hidden probabilities or outcomes through
  player knowledge until the existing observation rules allow it.

## Data Model / Content Boundary

Use `LootTable`/`LootTableEntry` through TEL-109. The authored files contain
IDs and weights only; `LootTableEngine` and TEL-105 remain authoritative for
selection and state mutation.

## Public API / Events

API classification: none for commands/events. Existing treasure events and
carried/secured wealth contracts remain unchanged.

## Determinism / Save Impact

Selection uses the existing scoped `loot-table` stream and saved
`content_version`; no new RNG stream or save field is introduced. Save impact
is none.

## Tests

- Validate every table has a unique ID, positive entries, stable ordering, and
  references only existing TEL-113 items.
- Reject empty tables, duplicate item IDs, unknown item IDs, zero/overflowing
  total weights, and out-of-slice references.
- Replay selection with equal inputs and assert equal item IDs.
- Resolve a selected item through TEL-105 and prove it remains carried until
  return to the inn; do not change treasure mechanics.

## Acceptance Criteria

- All first-slice loot references resolve to valid TEL-113 item definitions.
- The existing loot engine selects deterministically from the authored tables
  and the existing treasure path preserves carried/unsecured wealth.
- Invalid table shape, weight, or item references fail pack validation.
- No permanent drop-rate, value, or loss formula is invented, and focused
  validation/replay tests pass.

## Definition of Done

The loot-table files, band/monster references, validation and deterministic
treasure fixtures, and documentation are complete; no loot algorithm or
wealth rule is added.
