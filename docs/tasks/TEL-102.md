# TEL-102 — Implement point-allocation character creation

## Status

Implemented and verified.

`POINT_ALLOCATION` now validates a configured six-attribute budget and
inclusive attribute bounds through the TEL-100 simulation boundary. The
resulting attributes are committed through the existing command/event path.

## Design Intent

Implement the `POINT_ALLOCATION` character creation mode with a validated,
configured attribute budget through the TEL-100 simulation boundary.

## Specification References

§5.1; §26; §26.2; §36; §42; §51.

## Dependencies

TEL-100.

## Requirements

- Accept six attribute allocations and validate them before mutation.
- Enforce a caller-supplied/configured fixed budget and attribute bounds.
- Commit the resulting player through the simulation command boundary.
- Preserve deterministic replay for equal allocation inputs.

## Non-Goals

- No permanent budget, minimum/maximum, cost curve, or derived-stat formula;
  unresolved values remain `CONFIGURATION/TUNING DECISION REQUIRED`.
- No rolled, daily-seed, equipment, or content behavior.

## Invariants

Invalid allocations do not mutate state or emit committed events. Equal valid
inputs produce equal authoritative results.

## Save Impact

Use the existing explicit save contract for the resulting attributes and add
DTO/migration coverage only if the persisted shape changes.

## Tests

- Exact-budget success and under/over-budget rejection.
- Attribute bound and malformed-input rejection.
- Validation-before-mutation, event, deterministic replay, and save coverage.

## Acceptance Criteria

`POINT_ALLOCATION` creates a valid six-attribute player with a configured
budget and complete validation, without inventing a permanent balance policy.

## Definition of Done

Focused implementation, headless tests, and documentation are complete; no
other creation mode or gameplay is implemented.

## Implementation Evidence

- Public API: `PointAllocationCharacterCreationInput` carries six requested
  attributes; `PointAllocationCharacterCreationConfiguration` supplies the
  fixed total budget and inclusive attribute bounds; and
  `PointAllocationCharacterCreationProvider` validates and commits the
  point-allocation result.
- Validation: missing or wrong-mode input, out-of-range attributes, and
  under/over-budget allocations are rejected before state replacement or
  event production. The configured budget is the sum of the six supplied
  allocation values; no additional cost curve is introduced.
- Invariants: the simulation remains authoritative, the existing
  `CharacterCreatedEvent` is emitted only by the committed command boundary,
  equal state/configuration/input values replay equally, and no renderer or
  hidden-information boundary changes.
- Save impact: none; `PlayerAttributes` already use the explicit player DTO,
  and save version 14 remains current. Canonical save serialization round
  trips the resulting attributes.
- Tests: `CharacterCreationTests` covers exact-budget success, under/over
  budget rejection, bounds and malformed-input rejection, state/event commit,
  deterministic replay, and save round trip.
- Follow-up: TEL-103 remains responsible for daily-seed character creation;
  balance policy and starting-loadout behavior remain outside this ticket.
