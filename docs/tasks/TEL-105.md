# TEL-105 — Implement treasure acquisition and loot resolution

## Status

Not started.

## Design Intent

Close the Core Alpha gap between item/content definitions and the expedition
loop by resolving found treasure into unsecured expedition state.

## Specification References

§1.1; §6.1; §9.5; §17; §29; §35–§36; §42; §48; §51.

## Dependencies

TEL-022, TEL-030, TEL-040, TEL-041, TEL-060, and TEL-061.

## Requirements

- Resolve a found treasure result into `ExpeditionState.AcquiredItems` and/or
  carried gold through a validated simulation command.
- Keep treasure unsecured underground and preserve the carried/secured wealth
  boundary.
- Use configured content and scoped deterministic RNG for random loot choices.
- Emit only committed, observed treasure facts.

## Non-Goals

- No new production content catalog, broad loot expansion, artifact-balance
  policy, or depth ecology.
- No identification, affix, curse, or equipment-policy redesign beyond
  integrating existing item contracts.

## Invariants

Loot cannot be acquired outside an active expedition or directly into secured
wealth. Equal seed/version/position/input state produces equal loot. Hidden
definition data and probabilities remain undisclosed.

## Save Impact

Persist acquired item instances and unsecured gold through the existing
explicit expedition DTOs; add migrations and round-trip tests if the shape
changes.

## Tests

- Gold and item acquisition through the command boundary.
- Invalid location/state and overflow boundaries.
- Deterministic loot replay, event payload, suspend/resume, and return-to-inn
  securing behavior.

## Acceptance Criteria

The player can find valuable treasure that remains unsecured underground and
is secured only by the existing validated return flow.

## Definition of Done

Focused implementation, headless/determinism/save tests, and documentation are
complete; no content expansion is implemented.
