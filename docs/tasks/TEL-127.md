# TEL-127 — Verify playable Godot vertical slice and art-production readiness

## Design Intent

Prove that real first-slice content and the production-shaped Godot client form
one complete player-usable loop, then evaluate whether the repository is ready
to author final production-art batches.

## Specification References

§3; §36–§39; §44–§48; §51–§52.

## Dependencies

TEL-110–TEL-116 and TEL-120–TEL-126.

- `docs/presentation/GODOT_CLIENT_BLUEPRINT.md`
- `docs/presentation/UX_INTERACTION_BLUEPRINT.md`
- `docs/presentation/ART_DIRECTION_BLUEPRINT.md`
- `docs/presentation/ASSET_PIPELINE_BLUEPRINT.md`

## Requirements

- Execute the complete Playable Godot Vertical Slice gate using real authored
  content and a fixed seed.
- Exercise keyboard and controller paths required by the gate.
- Verify authoritative equivalence across save/resume.
- Confirm no required gameplay step depends on developer/debug commands.
- Record presentation-only defects separately from gameplay/architecture gate
  failures.
- Complete the Art Production Ready review: art-direction constraints, asset
  registry/pipeline, first-slice production matrix, placeholder coverage, and
  repository binary policy must be explicit enough to authorize final batches.
- If the playable gate passes but art readiness does not, record that split
  result and leave production-art work blocked.

## Non-Goals

- No final production art batch in this ticket.
- No broad 50-floor content expansion.
- No weakening acceptance criteria to accommodate unavailable Godot tooling.

## Invariants

The acceptance run uses the same renderer-independent simulation/save/content
contracts as headless verification. Visual acceptance must not create separate
gameplay truth.

## Save Impact

None expected from the acceptance work itself.

## Tests / Observation

- All checks required by both gate documents.
- Canonical full repository verification.
- Real Godot fixed-seed client acceptance with recorded Godot/runtime version.
- Keyboard/controller observations.
- Save/resume authoritative-state comparison.

## Acceptance Criteria

`GODOT-PLAYABLE-SLICE` has recorded passing evidence. `ART-PRODUCTION-READY`
has either recorded passing evidence or a precise remaining blocker. Production
art tickets may be authored only when the latter gate passes.

## Definition of Done

Update the active umbrella ExecPlan with results. Move it to completed only when
the Playable Godot Vertical Slice is complete and Art Production Ready has
passed. If art readiness remains blocked, keep the plan active or create an
explicitly scoped follow-up without marking production art eligible.
