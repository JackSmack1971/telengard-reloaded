# TEL-108 — Add deterministic developer debug commands

## Status

Not started.

## Design Intent

Provide the minimum renderer-independent developer command surface required to
diagnose and reproduce Core Alpha behavior.

## Specification References

§35; §36; §43; §44; §45; §51–§52.

## Dependencies

TEL-003, TEL-006, TEL-107, and the owning gameplay tickets for each command.

## Requirements

- Extend the existing headless tooling with the §43 commands: teleport,
  state setters, item/gold grants, monster/feature spawning, danger control,
  reveal commands, trigger death, RNG inspection, state/knowledge dumps, and
  save/load.
- Keep mutations routed through the same public simulation command boundaries
  as normal consumers.
- Support `--seed <seed> --deterministic` scripted execution and stable,
  machine-readable output for replay/debug comparison.

## Non-Goals

- No renderer console, cheat policy, production UI, or post-alpha tooling.
- No direct mutation of `GameState` from the tool.
- No new gameplay behavior merely to make a debug command convenient.

## Invariants

Debug commands are deterministic for fixed inputs, preserve validation and
event ordering, and do not expose hidden facts through ordinary player-facing
events. Diagnostic output may be privileged tooling output.

## Save Impact

Use the existing explicit save boundary. Do not introduce a second save format
or alter persisted versions solely for tooling.

## Tests

- Command parsing and stable output for every §43 command.
- Validation and simulation-boundary routing for mutating commands.
- Deterministic replay and save/load comparison using the tool.
- Invalid input and unavailable-system diagnostics.

## Acceptance Criteria

Developers can reproduce, inspect, and manipulate the Core Alpha scenario with
the §43–§44 command surface without moving authority into tooling.

## Definition of Done

Focused tooling implementation, headless tests, and documentation are
complete; no post-alpha system or production content is added.
