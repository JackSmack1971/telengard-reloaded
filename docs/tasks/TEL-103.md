# TEL-103 — Implement daily-seed character creation

## Status

Implemented and verified.

`DAILY_SEED` now derives six bounded attributes from a stable caller-supplied
seed token and an explicit roll-policy version through the simulation boundary.

## Design Intent

Implement the `DAILY_SEED` creation mode so equal daily-seed inputs produce the
same initial roll conditions through the deterministic simulation boundary.

## Specification References

§8; §26; §26.3; §42; §44; §51.

## Dependencies

TEL-002 and TEL-100.

## Requirements

- Accept a stable daily-seed value/token and derive the initial creation
  conditions deterministically.
- Ensure equal daily-seed inputs produce equal initial roll conditions for all
  players, independent of renderer or process state.
- Keep the roll policy configurable and reuse the TEL-101 boundary where
  appropriate.

## Non-Goals

- No undocumented timezone, reset time, calendar source, or server authority
  policy; those remain `CONFIGURATION/TUNING DECISION REQUIRED`.
- No point allocation, ordinary rolled mode, world-seed selection, or content
  expansion.

## Invariants

The daily seed is the complete authoritative input for the mode's initial roll
conditions. No wall clock or uncontrolled global RNG may affect the result.

## Save Impact

Persist the selected creation input only if required by the profile contract;
preserve explicit save versions and add migrations for any new persisted field.

## Tests

- Same daily seed gives equal attributes/conditions across independent runs.
- Different seed inputs are not accidentally collapsed.
- Invalid token/input, event, replay, and save boundaries are covered.

## Acceptance Criteria

`DAILY_SEED` produces reproducible initial roll conditions from a stable input,
with no silently invented calendar policy.

## Definition of Done

Focused implementation, headless tests, and documentation are complete; no
other creation mode or gameplay is implemented.

## Implementation Evidence

- Public API: `DailySeedCharacterCreationInput` carries the stable seed token;
  `DailySeedCharacterCreationConfiguration` supplies the explicit policy
  version and inclusive attribute bounds; and
  `DailySeedCharacterCreationProvider` generates the six attributes.
- Determinism: the provider uses a scoped `character-creation` / `daily-seed`
  stream with the policy version as the RNG compatibility version. The player
  identity, world seed, wall clock, and process state do not affect the roll.
- Validation: blank or malformed input, wrong mode, and invalid configuration
  are rejected before the resolver can replace player state or emit an event.
- Invariants: the simulation remains authoritative, the existing committed
  `CharacterCreatedEvent` is reused, and no calendar, timezone, reset-time, or
  anti-reroll policy was invented.
- Save impact: none; only generated `PlayerAttributes` enter the existing
  explicit player DTO, and save version 14 remains current.
- Tests: `CharacterCreationTests` covers cross-player replay, different seed
  values, bounds, malformed input, event/state atomicity, and save round trip.
- Follow-up: TEL-101 remains not started on the remote baseline; starting
  loadout and daily-calendar policy remain outside this ticket.
