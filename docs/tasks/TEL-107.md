# TEL-107 — Add the Core Alpha vertical-slice integration proof

## Status

Implemented and verified.

## Design Intent

Provide one deterministic, headless end-to-end scenario proving that the
existing systems compose into the representative first vertical slice and
the Core Alpha success test.

## Specification References

§44–§45; §48; §51–§52.

## Dependencies

TEL-100–TEL-106 and the existing TEL-010–TEL-093 slices required by the
scenario.

## Requirements

- Drive character creation, preparation, dungeon entry, exploration,
  feature/encounter interaction, treasure, descent or retreat, death/escape,
  banking, knowledge update, and restart through public simulation commands.
- Compare authoritative state/events after deterministic replay and save/load.
- Use test fixtures/configuration for the representative slice without
  adding production content catalogs.
- Record which Core Alpha checklist items are covered by the scenario.

## Non-Goals

- No production content expansion to the §48 counts of floors, monsters,
  items, spells, or biomes.
- No renderer implementation or new gameplay formula.
- No replacement of focused tests owned by individual TEL tickets.

## Invariants

The same seed, versions, initial state, and command sequence reproduce the
same authoritative state and event stream. Presentation does not own logic.

## Save Impact

No production save change is expected. If the integration exposes a missing
persisted field, stop and assign the owning state/save work explicitly rather
than bypassing DTOs.

## Tests

- Full scripted success-path replay.
- Failure/death and return-to-inn branches.
- Suspend/resume and save/load equivalence.
- Hidden-information, carried/secured wealth, and knowledge assertions.

## Acceptance Criteria

One headless deterministic scenario demonstrates the §48 loop and gives
auditable evidence for every applicable §51–§52 Core Alpha requirement without
creating content-expansion work.

## Definition of Done

The integration test/harness and evidence documentation are complete; no
production content expansion is implemented.

## Implementation Evidence

- Added `CoreAlphaIntegrationTests` with a configured floor-1 fixture. The
  success script uses the existing character creation/setup boundaries, then
  dispatches dungeon entry, fountain activation, movement-triggered encounter,
  threat assessment, attack, explicit monster knowledge, treasure acquisition,
  suspension, save/reload continuation, retreat to the floor entrance, and
  banking.
- Added a Legacy failure script that dispatches knowledge, unsecured treasure,
  suspension, death, save/reload, and `ReplaceLegacyCharacterCommand`; it
  verifies treasure loss, return to the inn, a recorded dead hero, and retained
  knowledge after restart.
- The test harness accepts an explicit initial state so configured integration
  fixtures can be replayed without adding production content catalogs.
- Determinism is checked through final save and event-signature equality for
  repeated runs and for uninterrupted versus save/reload execution. The test
  also asserts unknown threat/knowledge before explicit observation and
  carried versus secured wealth at the return boundary.
- Save impact: none; save version 14 and all existing DTOs/migrations remain
  unchanged.
- Deferred: production content packs (TEL-109–TEL-116), developer debug
  commands (TEL-108), and renderer/client integration remain separate work.
