# TEL-112 — Author first-slice encounter ecology tables

## Status

Implemented and verified.

## Implementation Evidence

- Added the validated encounter-table schema and `ContentPack.EncounterTables` catalog.
- Added the Upper Ruins floors 1–5 table referencing all eight TEL-111 monster IDs.
- Added contiguous floor coverage, duplicate/weight/overflow, unknown-monster, and band-reference validation.
- Added weighted deterministic selection to the existing encounter trigger configuration; no new trigger boundary or event was introduced.
- Spawn level, hit points, weights, and trigger chance remain content/caller configuration pending product tuning.
- Save impact: none. The existing `content_version` remains the compatibility
  key; legacy unit-weight encounter callers preserve their prior deterministic
  vector, while weighted selection uses the explicit `selection:weighted-v1`
  scope.

## Design Intent

Author deterministic, data-driven encounter tables for the floor 1–5 band
that select from the TEL-111 monster roster through the existing encounter
trigger boundary.

## Specification References

§9.4; §10; §14–§18; §31; §34; §42–§48; §51.

## Dependencies

- TEL-109 — catalog, table schema, validation, and `content_version`.
- TEL-110 — floor 1–5 band identity and ecology references.
- TEL-111 — monster IDs available for encounter entries.
- TEL-031 — existing deterministic encounter trigger consumer.

## Requirements

- Provide data-driven encounter tables for every floor band covered by the
  first slice, without adding floors outside 1–5.
- Reference only TEL-111 monster IDs and validate entry fields, weights, and
  floor/band coverage through the complete pack loader.
- Preserve stable entry ordering and explicit weights/selection policy in the
  content schema.
- Adapt table data to the existing encounter trigger configuration; do not
  duplicate encounter resolution, monster spawning, or combat rules.
- Keep any ecology inputs not specified by the product contract configurable.

## Non-Goals

- No new encounter trigger algorithm, combat behavior, pre-spawned dungeon
  population, depth system, noise/time/player-condition model, or renderer
  logic.
- No permanent encounter probability, level, hit-point, weight, or pacing
  choice where the specification is silent. Mark it
  `CONFIGURATION/TUNING DECISION REQUIRED`.
- No references to monsters outside the first-slice roster.

## Invariants

- Encounter selection remains in the simulation/content boundary and is
  validated before state mutation.
- Equal seed, versions, position, table, and command inputs select equal
  results through the existing scoped RNG.
- Monster definitions remain hidden until the existing observation contract is
  satisfied.

## Data Model / Content Boundary

Use the TEL-109 encounter-table representation and map entries to the
existing `EncounterSpawnOption`/trigger configuration. Table files contain
references and configuration only; they do not contain executable behavior.

## Public API / Events

API classification: none for commands/events. Existing encounter events and
payloads remain unchanged.

## Determinism / Save Impact

The table is static content. Selection continues to use the existing scoped
deterministic RNG and saved `content_version`; do not introduce a shared or
ambient random stream. Save impact is none.

## Tests

- Validate floor 1–5 coverage, unique table IDs, positive weights, and
  resolved monster references.
- Reject gaps, overlaps, out-of-range floors, zero/overflowing total weights,
  duplicate entries, and unknown monster IDs.
- Replay the same encounter inputs and assert equal selected definition and
  event/state results.
- Prove the table is consumed by the existing trigger resolver without
  moving authority into the content file.

## Acceptance Criteria

- Data-driven encounter tables cover the first-slice floors 1–5 and reference
  only the TEL-111 roster.
- The existing encounter trigger can consume the tables deterministically
  without a command/event contract change.
- Invalid coverage, weights, or references are rejected by pack validation.
- Focused ecology validation and deterministic replay tests pass, with
  unresolved tuning explicitly retained as configuration.

## Definition of Done

The encounter table files, band references, validation/replay tests, and
documentation are complete; no new encounter or combat algorithm is added.
