# TEL-106 — Preserve Legacy knowledge across character replacement

## Status

Implemented and verified.

The simulation now validates and commits replacement of a recorded dead Legacy
character at the inn. The replacement receives a fresh character and
expedition state while persistent journal/map knowledge, Legacy history, world
state, and secured progress remain available.

## Design Intent

Implement the Core Alpha profile handoff that preserves player knowledge when
a Legacy character dies and a new character is created.

## Specification References

§23; §28; §30.2; §31; §32.1; §48; §51.

## Dependencies

TEL-080, TEL-081, TEL-083, TEL-100, TEL-104, and TEL-051–TEL-056.

## Requirements

- Keep journal/map knowledge in the persistent profile/legacy state when a
  Legacy character is replaced.
- Make the new character observe the retained knowledge through simulation
  state, without exposing hidden dungeon definitions.
- Define the committed death-to-new-character handoff and validate it before
  replacing character state.

## Non-Goals

- No new death-loss formula, grave, corpse, heirloom, or previous-hero
  behavior; those remain in the existing legacy tickets.
- No knowledge-confidence formula or new knowledge category.
- No content expansion or renderer logic.

## Invariants

Character power may reset while player knowledge accumulates. The handoff is
deterministic, atomic, save-compatible, and does not reveal unobserved facts.

## Save Impact

No save-schema change. Existing explicit `KnowledgeState`, `LegacyState`,
`PlayerState`, and expedition DTOs persist the handoff result; save version 14
and existing migrations remain current. Round-trip coverage confirms retained
knowledge and Legacy history.

## Tests

- Knowledge survives Legacy death and new-character creation.
- Character-specific state resets only as specified by existing death mode.
- Invalid mode/state rejection, hidden-information boundaries, and profile
  save round trip.

## Acceptance Criteria

The Core Alpha requirement “knowledge persists between Legacy characters” is
demonstrated through authoritative state and explicit persistence.

## Definition of Done

Focused implementation, headless/save tests, and documentation are complete;
mode-specific behavior outside the handoff is not implemented.

Verification: `LegacyCharacterReplacementTests` passed (6 tests), formatter
verification passed, and the canonical full verification gate passed with the
final diff. No new death-loss, knowledge-confidence, content, renderer, or
save-version policy was added.
