# TEL-115 — Author the first-slice spell roster

## Status

Implemented and verified.

## Design Intent

Author 6–8 first-slice spell definitions for the existing spell casting and
knowledge boundaries.

## Specification References

§9.5; §12; §34; §40–§42; §48; §51.

## Dependencies

- TEL-109 — content-pack and validation boundary.
- TEL-072 — spell definition schema.
- TEL-073 — spell-casting consumer contract.

## Requirements

- Author between 6 and 8 unique spell definitions, inclusive.
- Provide targeting, effects, interactions, costs, initial descriptions, and
  discovered descriptions using the existing `SpellDefinition` fields.
- Ensure each definition is consumable by the existing `ISpellDefinition`
  and casting boundary without adding spell behavior to content files.
- Keep IDs, descriptions, and tag ordering stable and validate duplicate tags
  and invalid costs before catalog publication.

## Non-Goals

- No new spell effects, targeting engine, resource model, discovery command,
  damage formula, or renderer behavior.
- No permanent spell balance, cost, effect magnitude, or interaction policy
  where the specification is silent. Mark it
  `CONFIGURATION/TUNING DECISION REQUIRED`.
- No spells outside the first-slice count.

## Invariants

- Spell definitions remain content; casting remains authoritative in the
  simulation/content resolver boundary.
- Hidden or undiscovered descriptions are not automatically placed in player
  knowledge by loading a catalog.
- Equal pack/version inputs produce equal spell definitions and deterministic
  replay remains governed by the existing casting contract.

## Data Model / Content Boundary

Use `SpellDefinition` loaded via TEL-109. Effects and interactions are stable
identifiers consumed by existing logic; they are not executable scripts.

## Public API / Events

API classification: none for commands/events. Existing spell-cast events and
command payloads remain unchanged.

## Determinism / Save Impact

Static spell loading has no RNG. Any random spell behavior must remain under
existing scoped, versioned simulation rules. Save impact is none.

## Tests

- Validate the inclusive 6–8 count, unique IDs, non-empty targeting/cost and
  description fields, and stable tag order.
- Validate effects/interactions against the existing supported contract where
  applicable; reject malformed definitions before catalog publication.
- Prove loading does not create spell knowledge or expose discovered text.
- Cast at least one representative definition through existing spell tests and
  assert no command/event or save contract changed.

## Acceptance Criteria

- The pack contains 6–8 valid, uniquely identified spells with all required
  targeting, effect, interaction, cost, and discovery-description fields.
- Existing spell casting can consume the definitions without new resolver or
  renderer logic.
- Hidden discovery text remains governed by existing knowledge contracts.
- Focused roster validation, deterministic-load, and casting regression tests
  pass, with unresolved balance retained as configuration.

## Definition of Done

The spell files, catalog references, validation/casting tests, and
documentation are complete; no spell mechanics or permanent balance policy is
added.
