# TEL-120 — Build playable Godot application host and bootstrap

## Design Intent

Create the application layer that turns the TEL-091 visual renderer boundary
into a real Godot session host without moving authoritative gameplay into Godot.

## Specification References

§3; §12; §34; §36–§39; §47–§48; §51.

## Dependencies

TEL-090–TEL-093, TEL-104, TEL-109.

## Required Blueprint Context

- `docs/presentation/GODOT_CLIENT_BLUEPRINT.md`
- `docs/exec-plans/active/GODOT-PLAYABLE-VERTICAL-SLICE.md`

## Requirements

- Add the smallest Godot application host/bootstrap boundary needed to create or
  load an authoritative simulation session.
- Load the external content pack through the existing TEL-109 boundary.
- Establish ownership of authoritative `GameState`, command dispatch, committed
  event collection, presentation projection, and renderer refresh outside
  visual scene nodes.
- Support a development startup path that can reach a valid inn/setup state
  without test-only frame injection.
- Keep Godot presentation optional for headless simulation verification.

## Non-Goals

- No full input mapping, simulation clock, UI flow, production art, or broad
  scene architecture beyond bootstrap needs.
- No duplicated gameplay/content rules in Godot.
- No TEL-110–TEL-116 authored content requirement beyond loading the pack shape.

## Invariants

Simulation remains authoritative. Godot resources/scenes do not become save
state. Content remains separate from presentation. No hidden state is exposed
merely to simplify bootstrap.

## Save Impact

Expected none. If bootstrap reveals a missing authoritative persisted field,
stop and assign the owning save/domain work explicitly.

## Tests / Observation

- Focused host/bootstrap tests where practical.
- Verify content pack/bootstrap failure handling.
- Verify projection refresh does not mutate authoritative state.
- Exercise the Godot startup surface when the environment supports the required
  Godot version; record the exact environment used.
- Run the canonical full repository verification for code changes.

## Acceptance Criteria

Launching the Godot project can initialize a real authoritative Telengard
session/content pack and supply renderer-safe state to the visual boundary
without test-only frame injection or presentation-owned gameplay state.
