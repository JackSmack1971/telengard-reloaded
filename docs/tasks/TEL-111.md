# TEL-111 — Author the first-slice monster roster

## Status

Not started.

## Design Intent

Author the representative first-slice monster ecology as 8–12 distinct
definitions using the existing monster schema and the TEL-109 content pack.

## Specification References

§9.4; §14–§18; §34; §43–§48; §51.

## Dependencies

- TEL-109 — content-pack and validation boundary.
- TEL-030 — monster definition schema.
- TEL-031 — encounter trigger consumer contract.

Loot-table IDs may be declared before TEL-114 is complete; complete-pack
validation must reject missing references once the full pack is assembled.

## Requirements

- Author between 8 and 12 unique monster definitions, inclusive.
- Use the existing family, base-stat, trait, resistance, vulnerability,
  action, behavior, spawn-rule, and loot-table fields.
- Make the roster ecologically distinct: use multiple families and meaningful
  differences in behavior, traits, actions, resistances, vulnerabilities, or
  spawn rules, not only scaled numeric statistics.
- Keep identifiers stable, display text content-only, and loot references
  explicit.
- Ensure every authored definition is valid for the existing encounter and
  threat/knowledge consumers without changing those consumers.

## Non-Goals

- No new combat actions, AI engine, threat formula, monster-instance rules,
  journal rules, or renderer behavior.
- No requirement to settle hit points, damage, resistance math, spawn rates,
  or loot balance; unresolved values remain
  `CONFIGURATION/TUNING DECISION REQUIRED`.
- No stat-scaled copies used to inflate the roster and no content beyond the
  first slice.

## Invariants

- Definitions remain hidden content until a qualifying observation records
  knowledge.
- Encounter selection and combat remain authoritative in simulation/content
  resolvers, not in data files or renderers.
- Stable IDs and `content_version` preserve deterministic lookup and replay.

## Data Model / Content Boundary

Use `MonsterDefinition` and its existing nested schema types. The roster is
loaded through TEL-109 and supplies configuration to TEL-031; it does not
create `MonsterInstance` runtime state.

## Public API / Events

API classification: none for commands/events. Authored definitions add no
domain events and do not change public combat contracts.

## Determinism / Save Impact

Static roster loading has no RNG. If an encounter later selects among these
definitions, the existing scoped deterministic encounter stream and
`content_version` remain authoritative. Save impact is none.

## Tests

- Load the roster and assert the inclusive 8–12 count and unique IDs.
- Validate every definition’s required fields and every loot reference in a
  complete pack.
- Assert the roster contains ecological differences beyond numeric scaling.
- Assert each definition can be consumed by the existing encounter fixture
  without renderer or knowledge leakage.
- Assert canonical repeated loads are equal.

## Acceptance Criteria

- The first-slice pack contains 8–12 valid, uniquely identified monsters.
- The roster uses all required schema areas and demonstrates multiple
  ecological/family/behavior differences rather than duplicate stat variants.
- Every monster loot reference resolves in the complete pack, and the existing
  encounter/threat/knowledge boundaries remain unchanged.
- Focused roster validation and deterministic-load tests pass.

## Definition of Done

The authored monster files, complete-pack references, focused tests, and
documentation are complete; no combat or balancing policy is implemented.
