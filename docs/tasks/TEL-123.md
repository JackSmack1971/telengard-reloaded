# TEL-123 — Expand production presentation contract and asset registry

## Design Intent

Make the Modern renderer boundary sufficient for real Godot scenes without
letting presentation query hidden simulation/content internals, and establish a
stable presentation-side resource registry with placeholder fallback.

## Specification References

§3; §34–§39; §42; §47–§48.

## Dependencies

TEL-090, TEL-091, TEL-109, TEL-120.

## Required Blueprint Context

- `docs/presentation/GODOT_CLIENT_BLUEPRINT.md`
- `docs/presentation/ASSET_PIPELINE_BLUEPRINT.md`
- `docs/exec-plans/active/GODOT-PLAYABLE-VERTICAL-SLICE.md`

## Requirements

- Audit `PresentationState`/`ModernRenderFrame` against graybox production needs.
- Add only renderer-safe observable identity/geometry/theme data that Godot
  legitimately requires.
- Preserve hidden-information redaction.
- Add a presentation-side stable-ID-to-resource registry boundary.
- Support explicit development placeholders for missing optional/final assets.
- Detect duplicate/invalid registry entries and required missing mappings as
  appropriate for this slice.
- Keep Godot resource paths/UIDs out of authoritative GameState/save DTOs.

## Non-Goals

- No final production assets.
- No broad content-schema redesign solely for Godot convenience.
- No raw hidden outcome/danger/monster-definition exposure.

## Invariants

Presentation consumes safe projections and committed events. Stable presentation
resource lookup does not change authoritative replay or save meaning.

## Save Impact

None expected. Presentation resource mappings are not authoritative save data.

## Tests / Observation

- Projection redaction and deterministic ordering tests.
- Registry duplicate/missing/fallback tests.
- Source-state immutability checks.
- Godot placeholder lookup observation.
- Canonical full verification for code changes.

## Acceptance Criteria

Godot can obtain the observable tile/environment/content presentation identity
needed for the first-slice graybox through documented projections and resolve
those identities through one presentation asset registry without reading hidden
Core state or embedding engine paths in authoritative data.

## Verification

- Status: implemented and verified. The Modern projection now exposes a stable
  environment theme, observed-tile connections, and presentation identity keys
  for discovered features and observed combat monsters.
- Save-schema impact: none; presentation mappings and Godot resource paths stay
  outside authoritative state and save DTOs.
- Registry: `PresentationAssetRegistry` validates duplicate keys, provides
  deterministic ordering, rejects missing required mappings when placeholders
  are disallowed, and returns an explicit development placeholder otherwise.
  Godot uses the same stable-ID lookup boundary for placeholder rendering.
- Evidence: focused projection/registry tests passed (9); Godot 4.7.2
  headless editor/runtime loading passed; host Debug build passed with zero
  warnings/errors; canonical Full verification passed with 447 Release tests.
