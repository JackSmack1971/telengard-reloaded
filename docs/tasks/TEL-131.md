## Status

Blocked behind TEL-129 and TEL-130. Third implementation slice for the
Five-Floor MVP Demo.

## Design intent

Make the fixed-seed demo start reliably playable by supplying an explicit
demo-ready authoritative player/configuration and closing the hosted combat
phase flow from encounter contact to a usable player action and continuation.

## Current gap

The Godot shell can submit several combat intents, but the normal desktop launch
path does not yet guarantee a usable gameplay configuration/player loadout or a
complete encounter-phase progression before those actions are selected. The MVP
needs one reliable combat path, not final combat breadth or balance.

## Requirements

- Define an explicit demo configuration path for any combat tuning already
  required by existing Core resolvers.
- Keep demo tuning/configuration visible and replaceable; do not silently freeze
  it as permanent game balance.
- Create the demo-ready authoritative player through existing character/setup
  boundaries, with enough HP/SP/known actions to demonstrate the selected MVP
  combat path.
- A fixed rolled/demo character and fixed seed are acceptable for this ticket.
- Ensure a newly triggered encounter can progress through the existing combat
  phases to a valid player-action state without debug intervention.
- Ensure at least one authoritative combat action can be selected, resolved,
  and followed by continued exploration for the fixed MVP route.
- Preserve current renderer-safe threat/encounter feedback and hidden-information
  rules.
- Keep already-implemented defend/flee/spell paths intact; broaden them only when
  necessary to prevent the MVP route from stalling.

## Non-goals

- No final combat formula or balance pass.
- No comprehensive enemy AI expansion unless a minimal existing phase boundary
  must be composed for continuation.
- No combat item-use requirement.
- No polished character-creation UI.
- No requirement to expose all three creation modes in Godot.
- No production art/audio.
- No save/resume.

## Invariants

Core resolves combat legality and outcomes. Presentation does not skip phases by
mutating state. Demo configuration is explicit. Deterministic behavior remains
stable for the fixed seed/configuration used by TEL-132.

## Save/version impact

Expected none. Demo configuration and transient presentation choices must not be
smuggled into save state. Any genuine authoritative state change follows the
existing explicit state/save contracts.

## Tests / observation

- Focused host tests for the demo launch configuration and authoritative starting
  player state.
- Encounter-phase integration test from contact through player action/resolution.
- Rejection tests proving invalid/mis-phased actions do not mutate state.
- Fixed-seed repeatability for the demonstrated combat path.
- Godot observation proving the player can encounter a monster, take the
  intended action, and continue exploring.
- Canonical full repository verification.

## Acceptance criteria

The normal MVP launch path produces a deterministic, demo-ready authoritative
player/session, and a naturally triggered encounter can reach and resolve a
usable player combat action through existing Core phase/action boundaries so the
five-floor run can continue without developer/debug commands.
