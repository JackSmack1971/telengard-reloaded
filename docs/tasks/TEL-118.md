# TEL-118 — Reconcile audit remediation status and documentation provenance

## Design Intent

Reconcile the five high-confidence documentation contradictions identified by the documentation consistency audit:

- AUD-001
- AUD-002
- AUD-005
- AUD-007
- P1-remediation status

Then decide whether `AUDIT_REMEDIATION_PLAYBOOK.md` and `docs/gates/AUDIT-P0.md` should remain manually maintained or be partially generated from canonical exec-plan/ticket status.

This is a documentation/process-governance ticket. It is fully independent of TEL-117 and must not wait for TEL-117 to land.

## Dependencies

None. TEL-118 must be implementable before, after, or without TEL-117.

## Requirements

For each of AUD-001, AUD-002, AUD-005, AUD-007, and the P1-remediation status:

- Identify the conflicting claims and exact document locations.
- Determine the authoritative status from implementation evidence, verification evidence, ticket/exec-plan state, and commit references.
- Preserve historical baseline and verification provenance.
- Correct stale status, priority, active/completed location, or “not started” claims.
- Record an as-of commit or verification reference for current status.
- Do not mark a remediation complete solely because implementation code exists; require the documented acceptance evidence appropriate to that packet.

Specific reconciliation targets include:

- Playbook machine-readable statuses currently marked open.
- `docs/gates/AUDIT-P0.md` claims that P1 remediation was not started.
- Active versus completed exec-plan placement, especially AUD-001.
- `docs/BUILD_STATUS.md` remediation summaries for AUD-002, AUD-005, and AUD-007.
- Duplicate status fields that can disagree without a documented precedence rule.

## Status-authority decision

Current decision: the machine-readable audit-status ledger is the authority for
current AUD-packet status, priority, severity, and compatibility sensitivity.
Completed exec plans are evidence/provenance, `docs/BUILD_STATUS.md` is
append-only verification history, and `docs/gates/AUDIT-P0.md` is a historical
snapshot.

TEL-119 implements the target decision: current machine-readable status and
verification metadata come from the ticket/exec-plan ledger, with generated
playbook/gate status views.

The current and target decisions must address:

- status, priority, severity, and ownership;
- active versus completed plan location;
- baseline/current commit references;
- verification results;
- human-authored rationale versus generated status fields.

If partial generation is chosen:

- define the canonical machine-readable input;
- define generated sections and markers;
- ensure generation is deterministic and reviewable;
- ensure human-authored evidence is not silently overwritten;
- add a validation/check that detects stale generated output.

If manual maintenance is retained:

- document the synchronization protocol;
- define required status fields;
- define the review/check that detects contradictions before completion.

## Non-Goals

- No production code or tooling changes.
- No coverage or mutation-number changes unless required to correct a directly identified documentation error and supported by existing evidence.
- No dependency on TEL-117.
- No broad rewrite of audit prose.
- No alteration of historical exec-plan evidence merely to make current status look cleaner.
- No automatic generation implementation unless the authority decision explicitly selects it.

## Invariants

- Documentation must not claim a remediation is open when authoritative evidence shows it is complete.
- Documentation must not claim P1 remediation was not started when covered P1 packets have verified completion evidence.
- Historical baselines remain identifiable and immutable.
- Current status includes a traceable commit or evidence reference.
- A reader can determine which artifact is authoritative without comparing several manually maintained documents.

## Tests

- Re-run the contradiction audit for the five named findings.
- Check every corrected claim against the cited implementation and verification evidence.
- Validate all changed relative links and referenced paths.
- Verify active/completed exec-plan placement against the chosen authority model.
- If generation is selected, run the generator twice and confirm identical output.
- If manual maintenance is retained, run the documented consistency/status validation.
- Confirm no TEL-117 files or behavior are required for completion.

## Acceptance Criteria

- All five named findings have an explicit final disposition: corrected, retained with documented historical context, or unresolved with an assigned follow-up.
- `AUDIT_REMEDIATION_PLAYBOOK.md` and `docs/gates/AUDIT-P0.md` agree with the selected status authority.
- P1-remediation wording is accurate as of a named evidence commit.
- Active/completed exec-plan status is internally consistent.
- The canonical-status-versus-manual-maintenance decision is documented.
- Any generated/manual synchronization rule is documented and verifiable.
- No claim depends on TEL-117 landing.
- No unrelated documentation is changed.
- Final documentation diff is reviewed against a clean declared base.

- Five contradiction findings are reconciled with evidence.
- Status authority and provenance rules are documented.
- The playbook/gate generation question is resolved.
- Historical evidence remains intact.
- The ticket is independently verifiable before, after, or without TEL-117.
