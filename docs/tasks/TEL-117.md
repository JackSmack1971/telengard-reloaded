# TEL-117 — Harden coverage and mutation tooling scope

## Design Intent

Make repository quality tooling explicit and safe about scope:

- `eng/coverage.ps1` separates production code from test-support tooling.
- `eng/mutation.ps1` supports independently verifiable scoped Stryker runs without allowing them to overwrite or masquerade as the full mutation baseline.

This is test/tooling infrastructure only. It does not change gameplay, simulation authority, save behavior, or game APIs.

## Requirements

- Add explicit project roles to `eng/coverage.ps1`:
  - `Production`: Core, Content, Save, Terminal.
  - `TestSupport`: TestHarness.
- Keep TestHarness measured and reported, but exclude it from the gated production aggregate.
- Preserve existing exclusions for Godot and generated/compiler-owned files.
- Add regression tests proving production totals exclude TestHarness and TestHarness totals remain visible separately.
- Preserve the default coverage command and production coverage failure behavior.

- Add `-AdditionalStrykerArgs` to `eng/mutation.ps1` and forward the values to Stryker.
- Preserve default mutation project scope and baseline behavior.
- Reject `--since` and `--with-baseline` when `-ResultsDirectoryName` is still `mutation-baseline`.
- Add regression tests verifying both guard cases reject with a nonzero/error result.
- Independently verify a valid scoped Stryker invocation with a non-default results directory.
- Record the scoped arguments in generated mutation metadata.
- Do not treat the default mutation run as sufficient verification of the scoped path.

- Audit root/nested `AGENTS.md` and `DEVELOPMENT` documentation for direct claims about this exclusion.
- Update only current operational documentation:
  - `docs/BUILD_STATUS.md`
  - `docs/test-quality-current-audit.md`
  - applicable `AGENTS.md`/`DEVELOPMENT.md` guidance
- Do not modify audit playbooks, audit gates, or completed exec-plan documents; those belong to TEL-118.

## Non-Goals

- No gameplay, simulation, save, RNG, renderer, command, or event changes.
- No new mutation exclusions, ignored-mutant rules, or score gate.
- No coverage-threshold change beyond clarifying production versus test-support scope.
- No rewrite of historical coverage or mutation results without fresh evidence.
- No changes to unrelated dirty files.

## Invariants

- Every in-scope production source file remains represented in the production coverage aggregate.
- Test-support code remains visible but cannot inflate or dilute the production gate.
- Default mutation behavior remains compatible.
- Scoped mutation output cannot overwrite the full baseline directory.
- Reports identify effective scope and invocation arguments.

## Tests

- Test that `--since` plus default `mutation-baseline` is rejected.
- Test that `--with-baseline` plus default `mutation-baseline` is rejected.
- Independent valid scoped-Stryker verification using a non-default results directory.
- Default coverage and mutation command verification.
- Documentation/path validation for updated current operational docs.

## Acceptance Criteria

- Before implementation, run `.agents/skills/doc-reality-audit/scripts/anchor-commit.ps1` and record the base commit SHA and dirty-tree state.
- Implementation begins from that recorded clean base commit in an isolated worktree or branch; the existing dirty worktree is not treated as the implementation base.
- Production and test-support coverage totals are separately reported.
- TestHarness is excluded from the production coverage gate.
- Both guarded scoped mutation forms are rejected against the default baseline directory.
- A valid scoped Stryker run succeeds independently and records its arguments.
- Default mutation behavior remains unchanged.
- Current operational documentation matches executable behavior.
- Final `git diff --name-only <base>...HEAD` contains only an explicit allowlist of intended scripts, tests, and current documentation.
- No unrelated files are present in the ticket branch/PR diff.
- `./eng/verify.ps1 -Mode Full` passes before completion.

## Definition of Done

- Focused tests, scoped-Stryker verification, and documentation updates are complete.
- No unrelated files are present in the ticket branch/PR diff.
- Default and scoped tooling paths have both been verified.
- Evidence and effective scope are documented.
