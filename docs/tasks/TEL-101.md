# TEL-101 — Implement rolled character creation

## Status

Implemented and verified.

The `ROLLED` mode is implemented through the TEL-100 simulation boundary with
an immutable six-range configuration and a named deterministic RNG stream. No
permanent roll formula or anti-reroll policy was introduced.

## Design Intent

Implement the `ROLLED` character creation mode through the TEL-100 simulation
boundary using configurable six-attribute rolling rules.

## Specification References

§5.1; §8; §26; §26.1; §42; §51.

## Dependencies

TEL-002 and TEL-100.

## Requirements

- Generate the six starting attributes through a caller-supplied/configured
  rolling policy.
- Use a named deterministic RNG stream derived from stable creation inputs.
- Commit one character result through the simulation command boundary.
- Preserve the separation between observed player attributes and hidden RNG
  inputs.

## Non-Goals

- No permanent attribute values, roll formula, reroll limit, or anti-reroll
  policy; the specification leaves the anti-reroll solution open.
- No point allocation, daily seed, starting loadout, or content expansion.

## Invariants

Equal seed, version set, initial state, command, and rolling configuration
produce equal authoritative state and events. Validation occurs before player
mutation.

## Save Impact

Assess the explicit profile and suspend DTOs for the generated attributes; add
versioned DTO/migration coverage if their persisted representation changes.

## Tests

- Deterministic replay for equal rolling inputs.
- Attribute-count, range, and invalid-configuration boundaries.
- Creation event/state commit and save round trip where applicable.

## Acceptance Criteria

`ROLLED` creates a valid six-attribute player through the simulation boundary,
with deterministic configured rolls and no silently selected anti-reroll rule.

## Definition of Done

Focused implementation, headless tests, and documentation are complete; no
other creation mode or gameplay is implemented.

## Implementation Evidence

- Public API: `RolledAttributeRange` and the immutable
  `RolledCharacterCreationConfiguration` accept six caller-supplied inclusive
  ranges plus a policy version; `RolledCharacterCreationProvider` owns the
  six-attribute `ROLLED` transition.
- Determinism: the provider uses the named `character-creation` stream scoped
  by rolled mode, player identity, and policy version, derived from world seed
  and simulation version. Equal state and configuration replay to equal state
  and events without coupling character rolls to dungeon generator changes.
- Authority/hidden information: the provider returns only the updated
  `PlayerState`; the existing committed `CharacterCreatedEvent` still exposes
  only player identity and mode.
- Save impact: none; generated attributes already use the explicit player save
  DTO and save version 14 remains current. A rolled result round-trips through
  the existing serializer.
- Tests: `CharacterCreationTests` covers six bounded attributes, distinctive
  configured ranges, deterministic stream replay, invalid configuration and
  provider boundaries, preservation of unrelated player state, event/state
  commit, and save round trip.
- Follow-up: TEL-102 and TEL-103 remain responsible for point-allocation and
  daily-seed modes; anti-reroll, balance, and starting-loadout decisions remain
  configuration or later ticket work.
