# TEL-091 — Build Modern renderer prototype

## Design Intent
Deliver the specification-defined build modern renderer prototype slice while preserving Telengard's expedition loop, mystery, and renderer-independent simulation.

## Specification References
§3; §12; §36–§39; §43–§45; §47–§48.

## Dependencies
Prior related work: TEL-085, TEL-090.

## Requirements
- Implement only build modern renderer prototype and the integration points explicitly implied by the cited sections.
- Keep authoritative state and rules in the simulation; keep content definitions separate from simulation logic.
- Use the existing command/event boundary and preserve the documented product non-goals.
- Do not invent mechanics where the specification is intentionally silent. Mark any such choice CONFIGURATION/TUNING DECISION REQUIRED.

## Non-Goals
- No unrelated gameplay, presentation, refactor, or new TEL ticket.
- No permanent formula, balance, content catalog, or anti-save-scumming policy unless separately decided.
- No authoritative logic in scenes, UI components, sprites, renderer objects, or engine callbacks.

## Invariants
- Simulation validates state-changing commands before mutation.
- Presentation reads state and consumes events; it does not directly mutate authoritative GameState.
- Deterministic replay, scoped RNG, hidden-information, wealth, knowledge, and version invariants remain true where applicable.
- Undefined formulas and balancing remain CONFIGURATION/TUNING DECISION REQUIRED.

## Data Model
`ModernRenderer.Create` produces an immutable `ModernRenderFrame` from the
TEL-090 `PresentationState`. The frame contains an inn/dungeon scene marker,
visual environment flags, ordered observed/visited/current map tiles,
discovered-feature markers, a HUD, a redacted combat overlay, and ordered
visual cues translated from committed domain events. The Godot prototype draws
that frame-shaped input and owns no simulation state.

## Public API
Additive: `ModernRenderer.Create`, `ModernRenderFrame`, and the small
renderer-only projection records/enums are new APIs. Existing commands, event
payloads, and `PresentationState` remain unchanged; there are no existing
consumers to migrate.

## Commands
None. The renderer consumes projections and committed events; it does not
create, validate, or resolve commands.

## Events
None added. Existing committed events are translated into safe visual cues;
`EncounterStartedEvent` is reduced to a combat-start cue rather than exposing
its internal monster instance payload.

## Determinism
No randomness is introduced. Tile and feature ordering is stable, and event
cues preserve committed event order.

## Save Impact
None. No authoritative state, save DTO, or version marker changed.

## Tests
- `ModernRendererTests` covers known-map projection, deterministic ordering,
  hidden-feature/monster redaction, committed-event cue ordering, read-only
  collections, and null validation.
- Existing `PresentationStateAdapterTests` remain the headless visibility
  boundary checks; graphical presentation is optional.

## Acceptance Criteria
- The behavior named by this ticket works through the simulation boundary.
- Relevant state, events, visibility, save, and deterministic replay checks pass.
- No undefined formula or balance rule was silently made permanent.

## Definition of Done
- Focused implementation, tests, and documentation are complete.
- Cited invariants remain true.
- The smallest relevant automated check passes.
- No gameplay outside this ticket is implemented.
