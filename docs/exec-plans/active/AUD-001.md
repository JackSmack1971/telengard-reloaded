# AUD-001 — Canonical deterministic RNG encoding

## Purpose / user-visible outcome

Deterministic RNG streams derive the same bytes across process cultures and
cannot merge distinct field tuples at delimiter boundaries. Generation,
encounter, feature, item, and combat replay use the canonical encoding.

## Scope and non-goals

In scope: AUD-001, `DeterministicRng`, its direct stream consumers, affected
fixed vectors, compatibility-version metadata, focused tests, and evidence
documentation.

Out of scope: AUD-002 and every other audit packet; unrelated hash-based IDs,
gameplay tuning, content changes, and persistence redesign.

## Current state

At baseline/current commit `ba18040778dc7128a0ad443b8c6db242a05a36ca`,
`DeterministicRng.CreateStream` builds a NUL-delimited string using ordinary
`long.ToString()` and hashes its UTF-8 bytes. The representation is both
culture-sensitive for some seeds and ambiguous for embedded NUL characters.
Fixed vectors exist in `DeterministicRngTests`, `FloorLayoutGeneratorTests`,
`EncounterTriggerTests`, and feature/content tests.

## Invariant impact

- Simulation remains the authority; no command, event, renderer, or content
  boundary changes.
- RNG remains scoped and ordered by the existing inputs.
- The new representation uses explicit little-endian fixed-width numeric
  fields and length-prefixed UTF-8 strings, including a scope count.
- No hidden-information, wealth, or renderer behavior changes.

## Save/version impact


The encoder changes outputs used by generation, replay-significant combat, and
content selection, so the current simulation, generator, and content versions
advance together. No authoritative field or DTO changes, so save schema and
migration code remain unchanged. Vectors from the prior encoding are not
silently retained; each changed vector is regenerated for the new compatibility
version and its reason is recorded in the completion evidence.

## Decision log

- Use little-endian `Int64` for the world seed and little-endian `UInt32`
  lengths/counts. Encode strings as UTF-8 with no culture-sensitive formatting.
- Keep field order explicit: world seed, generator/content version, stream
  name, scope count, then scopes in caller order.
- Bump current simulation/generator/content compatibility versions because the
  same inputs otherwise produce different replay/generation/content outcomes.
