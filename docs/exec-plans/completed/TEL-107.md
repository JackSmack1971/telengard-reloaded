# TEL-107 Core Alpha integration proof

## Purpose / user-visible outcome

Provide an auditable, deterministic headless proof that the existing
simulation boundaries compose into the representative Core Alpha loop.

## Scope and non-goals

- In scope: one success-path replay, one Legacy death/replacement replay,
  feature and encounter interaction, treasure and knowledge commands,
  return-to-inn banking, suspension, save/reload continuation, and stable
  replay assertions.
- In scope: test fixtures for a generated floor layout and one feature and
  encounter configuration; no production content catalog.
- Out of scope: production gameplay changes, renderer implementation, content
  expansion, new formulas, and replacing focused subsystem tests.

## Current state

The repository had public command/resolver boundaries and a deterministic
save-aware test harness, but no single test covered the Core Alpha loop across
those boundaries. Suspension is an event-only boundary; a save reload followed
by more commands is the current continuation/resume behavior.

## Invariant impact

- Authoritative state remains in `Telengard.Core`; the integration only invokes
  public commands/resolvers through a dispatcher.
- Determinism is checked through equal final saves and typed JSON event
  signatures, including save/reload checkpoints and uninterrupted controls.
- Hidden monster details are not added to knowledge until an explicit
  observation command; feature and encounter fixtures remain test-only.
- Carried treasure is asserted before return and secured gold/inventory only
  after return; Legacy knowledge survives character replacement.
- No renderer or production content boundary changes.

## Save/version impact

None. Existing save DTOs and migrations are exercised without changing the
persisted shape or version markers.

## Implementation plan

1. Add a focused `CoreAlphaIntegrationTests` fixture that registers the
   existing public command handlers and drives success and Legacy failure
   scripts.
2. Assert event ordering, hidden-information and wealth boundaries, feature
   activation and journal observation, encounter defeat, suspend/save/reload
   continuation, death, and retained knowledge on replacement.
3. Update TEL-107, the task ledger, `BUILD_STATUS.md`, and `CHANGELOG.md` with
   the verified evidence and deferred scope.

## Surprises / discoveries

- The current suspension API emits `GameSuspendedEvent` without changing
  state; the proof treats save/reload plus subsequent commands as continuation.
- The repository already had the required test harness and gameplay
  boundaries, so no production support code was required.
- The initial return fixture needed a deterministic path from the encounter
  neighbor to floor-1 `StairsDown`, not a one-step reversal to `StairsUp`.

## Decision log

- Use configured test fixtures rather than authored production content, as
  required by TEL-107 and to avoid starting TEL-109–TEL-116.
- Use Legacy for the failure branch so the proof also covers the Core Alpha
  knowledge handoff and restart behavior delivered by TEL-106.
- Compare event payloads with typed JSON serialization so collection-valued
  observations/effects are included in replay evidence.

## Results / remaining work

Implemented the two-script headless proof and the explicit-initial-state test
harness overload. Independent review findings were resolved by adding feature
journal coverage, uninterrupted Legacy comparison, explicit treasure checkpoint
assertions, concrete fixture payload assertions, non-vacuous event ordering,
and typed JSON event signatures. Production content and debug commands remain
deferred to their TEL tickets.
