# TEL-110 — Author the floors 1–5 dungeon biome and band data

## Purpose / user-visible outcome

The versioned content pack exposes one renderer-independent `DungeonBandDefinition`
for the Upper Ruins representative slice. Floors 1 through 5 resolve to that
band; floors outside the slice do not.

## Scope and non-goals

- Add the engine-independent band schema, immutable catalog, JSON loader support,
  and one `content/bands/upper-ruins.json` record.
- Add focused loader and floor-coverage tests plus required status documentation.
- Do not add encounter, loot, feature, monster, layout, movement, renderer, or
  save behavior. Later TEL-112, TEL-114, and TEL-116 work owns those ecology
  definitions and completes the declared references.

## Current state

TEL-109 loads immutable JSON catalogs for existing content schemas, but it has
no band schema or `ContentPack.Bands` catalog. The pack has no authored band
files.

## Invariant impact

The band is configuration only; it does not mutate simulation state, emit
events, consume RNG, reveal knowledge, or add renderer dependencies. Directory
ordering remains ordinal and catalog ordering remains stable. Floor coverage is
validated before a band is published.

## Save/version impact

None. No authoritative state, DTO, migration, save version, or persisted
content-version contract changes.

## Implementation plan

1. Add validated `DungeonBandDefinition` and `ContentPack.Bands`.
2. Load `content/bands/*.json` in ordinal order and expose stable floor lookup.
3. Add the Upper Ruins floors 1–5 data and focused valid/invalid/deterministic
   tests.
4. Update the TEL ledger, ticket, build history, and content format docs.
