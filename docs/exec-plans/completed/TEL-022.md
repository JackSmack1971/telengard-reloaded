# TEL-022 — Carried gold

## Purpose / user-visible outcome

The simulation can commit gold acquired during an active dungeon expedition
to its unsecured carried-gold pool and report that committed fact to consumers.

## Scope and non-goals

Only TEL-022: carried gold state, acquisition command/resolver, event, and
explicit save round-trip compatibility. Secured gold, banking at the inn,
death handling, loot generation, and expedition completion remain out of
scope.

## Sources of truth

- `docs/modern-telengard-spec.md` §§1, 6, 28–33, 47–48
- `docs/tasks/TEL-022.md`
- `docs/INVARIANTS.md`, `docs/ARCHITECTURE.md`, and `docs/DEVELOPMENT.md`
- Existing `ExpeditionState`, `DungeonWalkingResolver`, save DTOs, and tests

## Current state

`ExpeditionState.CarriedGold` and its DTO field already existed, but no command
could acquire gold. `PlayerState.CarriedGold` is an existing scaffold field;
TEL-022 keeps it for compatibility and mirrors the expedition-owned unsecured
pool into it.

## Invariant impact

- Acquisition validates before mutation and only succeeds during an active
  expedition away from the inn.
- `GoldAcquiredEvent` is emitted after the committed state result.
- Player and expedition carried-gold mirrors remain equal and non-negative.
- No randomness, hidden information, content, or presentation authority is
  introduced.
- Secured wealth is untouched; no banking behavior is implemented here.

## Save/version impact

No save schema change: carried gold was already explicitly serialized in the
player and expedition DTOs at save version 3, and older migrations retain their
existing zero default.

## Implementation

- Added `AcquireGoldCommand`, `GoldAcquiredEvent`, and
  `CarriedGoldResolver.Acquire` under `Telengard.Core.Economy`.
- Kept dungeon entry's existing carried-gold mirror aligned.
- Added focused positive, deterministic, invalid/boundary, event, and save
  round-trip tests.

## Decision log

- Keep `PlayerState.CarriedGold` unchanged because TEL-022 does not require a
  public API removal; use `ExpeditionState.CarriedGold` for expedition wealth
  and mirror the value to the existing player field.
- Reject zero and negative acquisition amounts. The specification defines the
  pool and transitions but no negative-adjustment mechanic; losses belong to
  later death/wealth work.
