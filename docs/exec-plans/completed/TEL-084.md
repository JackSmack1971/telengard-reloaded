# TEL-084 ExecPlan — Implement graves

## Purpose / user-visible outcome

Legacy-mode death leaves a persistent grave marker at the hero's death
position. The marker survives explicit save/load and can support later dungeon
encounter work without adding encounter or loot mechanics to this ticket.

## Scope and non-goals

- Scope: TEL-084 only; Legacy grave state, death integration, explicit save
  DTO/migration, focused tests, and status/changelog documentation.
- Non-goals: grave encounters, loot recovery, corpse behavior, heirlooms,
  character replacement, Adventure tuning, presentation, and TEL-085.

## Sources of truth

- `docs/modern-telengard-spec.md` §§6, 30–31, and 43–45.
- `docs/tasks/TEL-084.md` and `docs/INVARIANTS.md`.
- Existing `LegacyState`, `DeadHeroRecord`, `PlayerDeathResolver`, and save
  DTO/migration tests.

## Current state

`LegacyState` persists the map and previous dead-hero records. Legacy death
already appends a `DeadHeroRecord`, but no grave collection exists. The
explicit save schema is version 11.

## Invariant impact

- The existing validated death command remains the sole state transition.
- Graves contain only stable observed death identity/location context; no
  hidden content, loot, or renderer state is exposed.
- No randomness, content catalog, wealth conversion, or presentation authority
  is added.
- Classic and Adventure death behavior remains unchanged.

## Save/version impact

The explicit save schema advances from 11 to 12. `LegacyStateDto` gains a
backward-compatible `Graves` collection and `GraveRecordDto`; version-11 and
earlier saves migrate to an empty collection. Simulation, generator, and
content versions remain unchanged.

## Implementation plan

1. Add immutable grave state and append one marker on Legacy death.
2. Add DTO conversion, validation, version-12 migration, and round-trip tests.
3. Update task/status/changelog documentation.
4. Run focused tests, formatter/build, full verification, and inspect scope.

## Surprises / discoveries

- The working tree contains unrelated untracked and modified files; they must
  remain untouched.
- The specification names graves but does not define loot, encounter, or
  balance behavior, so this slice records only stable hero/death location data.

## Decision log

- Use `GraveRecord(HeroId, Position, ExpeditionId)` as the smallest persistent
  marker that identifies whose grave exists, where it is, and which expedition
  produced it. Equipment, gold, corpse, and heirloom contents remain deferred.
- Append graves only for Legacy death because Classic deletes the character and
  Adventure returns the retained character to safety.
