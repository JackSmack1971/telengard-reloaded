# TEL-050 — KnowledgeEntry model

## Purpose / user-visible outcome

The simulation has an immutable, player-observed knowledge-entry model that can
be persisted and restored without exposing hidden content definitions.

## Scope and non-goals

Scope is TEL-050: `KnowledgeEntry`, its `KnowledgeState` collection boundary,
explicit save DTOs, migration from the current save schema, and focused tests.

Out of scope: observation ingestion, sample-count updates, confidence
progression, monster/feature knowledge, teleporter mapping, presentation, and
all later TEL tickets.

## Current state

`KnowledgeState` is an empty runtime record. `GameStateSaveDto.Knowledge` is an
`EmptyStateDto`, and saves currently use schema version 7. Feature outcomes
already carry opaque observation tags, but no journal model consumes them.

## Invariant impact

- State remains authoritative in Core; no renderer or content dependency is
  introduced.
- Entries contain only observed strings and aggregate fields; hidden content
  definitions are not copied into knowledge.
- No command, event, or RNG behavior is added, so command ordering and replay
  behavior are unchanged.
- Collection inputs are copied and validated at domain/DTO boundaries.

## Save/version impact

The save schema advances from 7 to 8. `KnowledgeStateDto` and
`KnowledgeEntryDto` persist the explicit model. Version 1–7 saves migrate with
an empty knowledge-entry collection; simulation, generator, and content
versions remain unchanged. Round-trip and migration tests cover the boundary.

## Implementation plan

1. Add the immutable Core entry and collection model with validation and copy
   semantics.
2. Replace the placeholder knowledge save DTO with explicit entry DTOs and add
   version-8 migration/validation.
3. Add focused model, save round-trip, and old-save migration tests.
4. Update verified status/ledger documentation after the full gate.

## Decision log

- Use an integer confidence constrained to 0–100 as a stored observation, not
  a progression formula; the specification leaves the formula to later work.
- Keep observations, hypotheses, and confirmed facts as copied unique strings;
  repeated samples belong to the later sample-count pipeline.
