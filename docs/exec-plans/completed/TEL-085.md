# TEL-085 ExecPlan — Implement heirlooms

## Purpose / user-visible outcome

Legacy death preserves the existing carried item identifiers as persistent
heirlooms associated with the dead hero. The heirloom collection survives
explicit save/load without changing Classic or Adventure death behavior.

## Scope and non-goals

- Scope: TEL-085 only; Legacy heirloom state, death integration, explicit save
  DTO/migration, focused tests, and status/changelog documentation.
- Non-goals: item selection or rarity balance, equipment-instance recovery,
  heirloom encounters or retrieval, character replacement, presentation, and
  any later TEL ticket.

## Sources of truth

- `docs/modern-telengard-spec.md` §§6, 30–31, and 43–45.
- `docs/tasks/TEL-085.md` and `docs/INVARIANTS.md`.
- Existing `LegacyState`, `PlayerState.Inventory`, `PlayerDeathResolver`, and
  save DTO/migration tests.

## Current state

`LegacyState` persists the map, dead-hero records, and graves. Legacy death
clears `PlayerState.Inventory` and equipment, but no heirloom state exists.
The current save schema is version 12.

## Invariant impact

- Authoritative heirloom creation remains in `PlayerDeathResolver`.
- Validation and mutation remain in one committed death transition; existing
  death/failure events remain unchanged.
- Captured identifiers are already present in authoritative player state, so no
  hidden item definition data or renderer state is exposed.
- No randomness, RNG stream, wealth, knowledge, or presentation authority is
  added.

## Save/version impact

The explicit save schema advances from 12 to 13. `LegacyStateDto` persists
heirloom records, and version-12-and-earlier saves migrate to an empty
collection. Simulation, generator, and content versions remain unchanged.

## Implementation plan

1. Add the compact runtime heirloom record and `LegacyState.Heirlooms`.
2. Append inventory-derived heirlooms during Legacy death before inventory loss.
3. Persist the collection with an explicit DTO and version-13 migration.
4. Add focused death, determinism, round-trip, migration, and validation tests.
5. Update the task ledger, build status, and changelog; run the repository gate.

## Surprises / discoveries

- The current runtime stores inventory as string identifiers and equipment as
  opaque instance IDs, but does not maintain an authoritative item-instance
  collection on `GameState`. This slice therefore preserves only the existing
  inventory identifiers.

## Decision log

- Use one `HeirloomRecord` per carried inventory identifier, keyed by the dead
  hero. This is the smallest persisted representation supported by the current
  state model and preserves duplicate inventory entries.
- Do not select by rarity, roll a percentage, retain equipment instances, or
  add retrieval behavior; the cited specification does not define those rules.

## Results / remaining work

Implemented and verified. The save schema advanced to version 13, and
version-12-and-earlier saves migrate to an empty heirloom collection.
Equipment-instance retention, item selection/balance rules, heirloom
encounters/retrieval, and character replacement remain intentionally deferred.
