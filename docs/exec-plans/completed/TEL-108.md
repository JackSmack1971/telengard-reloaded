# TEL-108 deterministic developer debug commands

## Purpose / user-visible outcome

Developers can run a seeded, deterministic script against the headless
simulation and inspect or manipulate the resulting state through stable JSON
output. The command surface covers the §43 debug commands and explicit save /
load checkpoints.

## Scope and non-goals

- In scope: TEL-108; `Telengard.TestHarness`; simulation-owned debug command
  boundaries for state-changing debug operations; focused harness/domain tests;
  status and changelog evidence.
- Non-goals: renderer consoles, production UI, cheat policy, content catalogs,
  new gameplay rules, and post-alpha tooling.

## Current state

The test harness initially accepted only `--seed <seed>` and optional
`--deterministic`. `SimulationTestHarness` already executed typed command
delegates and compared final saves/events across replay and save/reload
checkpoints.

## Invariant impact

- State-changing debug actions dispatch simulation-owned commands and return
  committed events; the harness does not assign `GameState` fields directly.
- Script replay uses the existing deterministic world/version inputs. RNG
  inspection creates a fresh scoped stream and does not consume gameplay RNG.
- Debug dumps are privileged tooling output; ordinary presentation events and
  hidden-information rules are unchanged.
- Content remains outside the harness; spawned definitions are explicit debug
  identifiers.

## Save/version impact

None. Debug mutations use fields already represented by save DTOs, and save /
load goes through `SaveGameSerializer`; save version 14 remains current.

## Public API and events

Added an additive simulation-owned developer-command boundary consumed by the
harness. Debug events identify committed operations and resulting facts;
existing gameplay commands/events are reused where their semantics already
match.

## Implementation

- Added validated debug commands for teleport, HP/level setup, grants, monster
  and feature spawning, and map reveal.
- Added the line-oriented script session with §43 commands, supporting dungeon
  entry/movement commands, structured errors, stable JSON Lines, save/load, and
  deterministic replay comparison.
- Preserved seed-only CLI behavior and added `--script <path>` and `--load
  <path>` options.
- Added focused parser/boundary/replay/save-load tests.

## Surprises / discoveries

- Local `main` was one commit behind `origin/main`; TEL-107 was present in the
  remote commit used as the TEL-108 branch base.
- The pre-existing worktree contains unrelated user changes; they were left
  unstaged and outside this slice.
- `SettingsState` is intentionally empty, so `set danger` remains transient
  harness configuration and is not persisted.

## Decision log

- Use line-oriented commands with `--script <path>` and compact JSON Lines
  output so transcripts are diffable and machine-readable.
- Keep `set danger` in the harness session because the current simulation has
  no authoritative danger field or canonical danger formula.
- Use existing gameplay resolvers whenever a debug action has the same
  semantics, and reserve new commands for privileged state setup or inspection.

## Results / remaining work

TEL-108 is implemented and documented. No renderer console, production cheat
policy, post-alpha tooling, or next TEL ticket was started.
