# TEL-093 renderer-independent save compatibility

## Purpose / user-visible outcome

Prove that an authoritative game state saved through the explicit save DTO
boundary can be loaded and rendered by both the Modern and Terminal
presentation boundaries with equivalent observable state. Hidden features and
internal monster details remain unavailable to either renderer.

## Scope and non-goals

- In scope: one headless integration test covering save/load, presentation
  projection, Modern rendering, Terminal rendering, hidden-information
  filtering, and source-state immutability.
- In scope: mark TEL-093 complete in the ticket ledger and verification
  history.
- Non-goals: gameplay, renderer APIs, save-schema changes, migrations,
  renderer host integration, and anti-save-scumming policy.

## Current state

The save boundary already serializes explicit `GameStateSaveDto` values and
migrates them to the current save version. `PresentationStateAdapter` already
filters undiscovered features and internal monster fields. Modern and Terminal
renderers already consume only that projection. No test currently proves that
these boundaries remain equivalent after a save/load round trip.

## Invariant impact

- Simulation authority remains in `GameState`; the test only observes it.
- Presentation receives a fresh immutable projection and cannot mutate the
  source state.
- Save/load preserves deterministic state and version fields.
- Hidden features and internal monster details remain redacted.
- Carried and secured gold remain separate in the projected state.

## Save/version impact

None. The test exercises the existing explicit save DTO and current save
version 14; no persisted shape, migration, or version marker changes.

## Implementation plan

1. Run the existing save and renderer tests as the pre-change baseline.
2. Add a focused cross-boundary test using a valid dungeon state with observed
   map data, discovered and hidden features, knowledge, carried/secured gold,
   and an active combat projection.
3. Serialize and deserialize the state, then assert canonical save equality,
   equal Terminal output, equal Modern observable fields, hidden-data
   redaction, and unchanged source serialization.
4. Mark TEL-093 implemented, append verification evidence, and update the
   unreleased changelog.
