# TEL-109 — Establish the data-driven vertical-slice content pack

## Purpose / user-visible outcome

The content boundary can load validated external JSON definitions into one
immutable versioned pack. Future first-slice content tickets can add authored
files without putting content tables in simulation or renderer code.

## Scope and non-goals

- In scope: a manifest with a required content version, typed catalogs for the
  existing content schemas, JSON file loading, duplicate-id validation, and
  cross-reference validation for existing loot and monster references.
- In scope: focused headless tests and content-definition documentation.
- Non-goals: authored first-slice data (TEL-110–TEL-116), encounter/band schema
  design, new gameplay rules, renderer behavior, and save-schema changes.

## Sources of truth

- `docs/tasks/README.md` TEL-109 entry.

- Existing schemas under `src/Telengard.Content` and their schema tests.

## Current state

`Telengard.Content` contains validated in-memory definitions for monsters,
items, spells, features, talents, and loot tables. The content directories
exist with only `.gitkeep` files, and there is no manifest, external loader, or
catalog boundary.

## Invariant impact

- Simulation remains authoritative; the loader only creates content
  definitions and does not mutate `GameState`.
- Content is immutable after loading and remains separate from runtime state and
  presentation.
- The manifest's content version is explicit and available to consumers for
  deterministic content selection. No ambient randomness is introduced.
- Hidden facts are not projected or exposed by the loader.

## Save/version impact

None. Existing `GameVersions.ContentVersion` and save version 14 remain
unchanged; the pack version is a content-input contract, not persisted runtime
state.

## Implementation plan

1. Add a versioned `ContentPack` and typed read-only catalogs.
2. Add a `ContentPackLoader` that reads `manifest.json` and one JSON definition
   per file from the existing content directories.
3. Validate required manifest/version fields, duplicate ids, and references
   between loaded monster loot tables and item/loot catalogs.
4. Add focused tests for valid loading, deterministic ordering, invalid JSON,
   duplicate ids, missing references, and content-version preservation.
5. Document the file contract for follow-on authored content tickets.

## Decision log

- Use one JSON object per file under the existing type directories so authored
  content remains reviewable and the loader does not invent a second table
  format.
- Keep band and encounter catalogs out of this slice because their schemas are
  not present yet and belong to later content tickets.

## Results / remaining work

TEL-109 is complete. The repository now has an explicit manifest/version,
typed immutable catalogs, deterministic JSON loading, schema-preserving parsing,
duplicate-id checks, and existing loot/monster reference validation. Focused
tests, formatter verification, and the full 401-test gate passed with zero
warnings and zero errors. Authored biome, roster, encounter, item, loot, spell,
and feature content remains deferred to TEL-110–TEL-116.
