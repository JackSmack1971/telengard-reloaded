# TEL-025 — Expedition suspension

## Purpose / user-visible outcome

An active expedition can be suspended through the simulation command boundary,
emitting a stable `GameSuspendedEvent`; the resulting full `GameState` can be
saved and loaded without losing the active expedition needed for resume.

## Scope and non-goals

- In scope: `SuspendExpeditionCommand`, its simulation resolver, the committed
  suspension event, and focused save/replay coverage.
- Out of scope: death handling, anti-save-scumming policy, encounter state,
  presentation integration, and later TEL tickets.

## Sources of truth

- `docs/tasks/TEL-025.md`
- `docs/modern-telengard-spec.md` sections 6, 32–33, 35–36, and 47–48
- `docs/INVARIANTS.md` and `docs/ARCHITECTURE.md`
- Existing `GameState`, `ExpeditionState`, command/event, and save DTO code

## Current state

`SaveGameSerializer` already round-trips the complete explicit `GameState`,
including active expedition state, but Core has no dedicated suspension command
or event.

## Invariant impact

- Authority remains in Core; presentation only submits the command.
- Suspension does not mutate authoritative state, so the active expedition can
  resume from the saved state.
- No randomness, hidden-information exposure, wealth transfer, or content
  behavior is added.

## Save/version impact

None. Existing version-4 DTOs already contain the state required by the
specified suspend save. No save shape or version changes.

## Implementation plan

1. Add the command, event, and resolver with active-expedition validation.
2. Add valid, invalid, deterministic, and save round-trip tests.
3. Update verified status after focused and full checks.

## Surprises / discoveries

The repository status document still describes dedicated suspension as absent,
while existing save DTO coverage already preserves active expedition state.

## Decision log

- Keep `ExpeditionState.Active` true when suspending; the saved state is the
  resume state, and the specification does not define a separate suspended
  runtime flag.
- Do not add anti-save-scumming metadata; the specification explicitly leaves
  that policy to a separate design decision.
