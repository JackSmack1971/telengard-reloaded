# TEL-083 ExecPlan — Persist dead hero records

## Purpose / user-visible outcome

Legacy-mode death records the deceased hero in persistent profile state so the
record survives explicit save/load and can support later grave and heirloom
work without changing the current expedition rules.

## Scope and non-goals

- Scope: TEL-083 only; Legacy dead-hero record state, explicit save DTO, schema
  migration, death integration, tests, and status/changelog documentation.
- Non-goals: character replacement, graves, heirlooms, Adventure tuning,
  Classic/Adventure death changes, presentation, and the next TEL ticket.

## Current state

`LegacyState` persists only `PersistentMap`. Legacy death preserves the dead
player in place but does not append a prior-hero record. The current explicit
save schema is version 10.

## Invariant impact

- Authoritative state remains in Core simulation and is changed through the
  existing validated death command boundary.
- Existing death events remain the committed event contract; no hidden data is
  emitted.
- No randomness, content, renderer authority, or wealth conversion is added.
- Classic and Adventure death behavior remains unchanged.

## Save/version impact

The explicit save schema advances from 10 to 11. `LegacyStateDto` gains a
backward-compatible `PreviousHeroes` collection and a DTO for
`DeadHeroRecord`. Version 10 and earlier saves migrate to an empty collection;
simulation, generator, and content versions remain unchanged.

## Implementation plan

1. Add immutable `DeadHeroRecord` state and append one record on Legacy death.
2. Add DTO conversion, validation, version-11 migration, and round-trip tests.
3. Update ticket/status/changelog documentation.
4. Run focused tests, formatter/build, full verification, and inspect scope.

## Decision log

- Use a compact record of stable identity/progression/death context rather than
  copying mutable runtime `PlayerState`; item retention belongs to later
  heirloom/grave work.
- Append records only for Legacy death because Classic deletes the character
  and Adventure retains the current character.
