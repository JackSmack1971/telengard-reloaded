# TEL-023 — Secured gold

## Purpose / user-visible outcome

Gold carried out of the dungeon is transferred to the persistent secured-gold
pool when the existing validated return-to-inn transition commits.

## Scope and non-goals

Only TEL-023: secured gold state, its save DTO/migration, and return-boundary
integration with a committed `GoldSecuredEvent`. Expedition completion,
death-loss rules, banking UI, and TEL-024 remain out of scope.

## Current state

`SecuredProgressState` now owns `SecuredGold`. `LeaveDungeonCommand` validates
the floor-1 return boundary and commits the carried-to-secured transfer while
preserving active expedition state for TEL-024.

## Invariant impact

- Core remains the sole authority; securing occurs inside the validated return
  resolver before the committed event is emitted.
- Carried gold becomes zero and secured gold increases by exactly the carried
  amount; no randomness or hidden information is involved.
- `Expedition.Active` remains unchanged because TEL-024 owns completion.

## Save/version impact

The explicit save DTO persists `SecuredGold` at schema version 4. Version 3 and
older saves migrate with zero secured gold; simulation, generator, and content
versions remain unchanged.
