# TEL-092 ExecPlan — Terminal renderer prototype

## Purpose / user-visible outcome

Provide a deterministic terminal presentation of the existing renderer-facing
simulation state and committed event cues using ASCII/symbolic text. A caller
can render the same state through the terminal boundary without changing
authoritative state or exposing hidden simulation details.

## Scope and non-goals

In scope: `Telengard.Terminal` terminal projection, stable map/HUD/expedition/
feature/combat text, safe committed-event cue text, focused headless tests,
and TEL-092 status documentation.

Non-goals: command parsing or input loops, new gameplay, content, save schema,
Godot changes, or renderer-owned simulation rules.

## Sources of truth

- `docs/tasks/TEL-092.md`
- `docs/INVARIANTS.md` and `docs/ARCHITECTURE.md`
- Specification sections 36–38
- `PresentationStateAdapter` and `ModernRenderer` as adjacent boundaries

## Current state

`src/Telengard.Terminal/Program.cs` contained only an empty entry point. The
Core presentation adapter exposed immutable, redacted `PresentationState`;
`ModernRenderer` established the existing event-to-cue and deterministic
ordering conventions.

## Invariant impact

The terminal renderer reads only `PresentationState` and committed events. It
does not reference or mutate `GameState`, consume RNG, resolve commands, or
render undiscovered features/internal monster fields. Output ordering is
stable for equal inputs.

## Save/version impact

None. No authoritative state, DTO, migration, or version marker changes.

## Implementation plan

1. Add a terminal renderer that emits stable ASCII/symbolic state lines and
   safe event cues from the existing Core presentation boundary.
2. Add focused tests for inn/dungeon projection, ordering, redaction, event
   handling, null validation, and deterministic repeatability.
3. Update TEL-092, the task ledger, changelog, and build verification record;
   complete this plan after the final gate.

## Decision log

- Use a single string-rendering API over the existing `PresentationState`
  rather than adding a second authoritative state model or command surface.
- Render only already-redacted presentation fields and summarize event types;
  raw encounter monster payloads and internal combat details remain hidden.
