# TEL-032 — Combat state machine

## Purpose / user-visible outcome

An encounter starts an authoritative combat state at contact, advances through
the specification-defined combat phases, and preserves the active combat in a
save so a suspended expedition can resume deterministically.

## Scope and non-goals

- In scope: combat phase/action-intent state, encounter integration, phase
  transition commands/events, and explicit save DTO/migration support.
- Out of scope: attack, defend, maneuver, spell/item effects, flee, threat
  formulas, enemy behavior, death, content catalogs, presentation, and
  TEL-033+.

## Current state

TEL-031 emits a runtime `EncounterStartedEvent` but retains no combat state.
The authoritative `GameState` and explicit save DTO already carry expedition
state and versioned migrations.

## Invariant impact

- Core validates combat commands before changing `GameState`.
- The encounter event is emitted after combat state is committed.
- No randomness or hidden definition data is added; action effects and threat
  calculations remain configuration/future-ticket decisions.
- Presentation remains a consumer of state/events and cannot mutate combat.

## Save/version impact

Save schema advances from version 4 to 5. Active combat stores the runtime
monster instance, phase, round, and selected action through explicit DTOs.
Version 1–4 saves migrate with no active combat.

## Implementation plan

1. Add immutable combat state, phases, action intents, transitions, and events.
2. Start combat from the existing deterministic encounter trigger and prevent
   unrelated dungeon boundary commands from bypassing active combat.
3. Add save round-trip/migration and headless lifecycle tests.
4. Run focused tests, formatting, and the full verification gate.

## Decision log

- Start at `Contact` because TEL-031 already owns the search/trigger boundary.
- Store action intent only; action resolution belongs to TEL-033–035 and later
  tickets, so no combat formula is made canonical here.

## Results / remaining work

TEL-032 is implemented and verified. Encounters commit contact combat state;
the state machine advances through threat assessment, player action,
resolution, enemy action, and state check, while preserving selected action
intent until the next player-action phase. Active combat is explicitly saved
at schema version 5. Attack/defend/maneuver effects, flee, threat formulas,
death, and combat-ending behavior remain later tickets.
